## 1. Outcome and authority

Deliver direct touch on desktop touchscreens, cancellable scrolling in Help and Saved Games (also usable by mouse drag), and the first installable Android prototype from the same engine. Test it on a physical arm64 phone early, before completing optional mobile screens. Android publicability remains a v1.4.0 target with v1.5.0 as the maximum horizon, not a requirement to publish Android in v1.3.9.

Phase 0 authorized planning only; implementation subsequently proceeded under the maintainer's explicit approvals. On 2026-10-28 the maintainer separately approved the bounded v1.3.9 experimental-prototype acceptance amendment in sections 6–7, without declaring missing device evidence passed. Merge, tags, releases/publication, deployment, destructive operations and credential/permission changes remain separate decisions. A branch or debug APK does not mean public Android readiness.

Preserve C11/SDL2/ttf/mixer; all modes/difficulties/Daily; revision-3 generation and revision-2 reconstruction; puzzle and attempt identity; Restart/Retry; normal/Daily independence; exact and legacy library views, Save/Load/View/Replay/Delete and receipts; checked persistence, recovery and incompatible-format handling; EN/ES/CA, themes, reduced motion, optional audio, offline operation; keyboard/event-local modifiers, mouse/right-click, regular/XL layouts, More and visible paging. Preserve Classic/Daily neutrality about the hidden solution. Keep pause reasons independent and the active board concealed while gameplay is paused.

Exclude engine rewrites, SDL3 migration, source-tree relocation, a general widget/platform framework, generator or storage-format changes, new modes, cloud/import-export, production signing/keys, public Android identity registration, store integration, a full accessibility bridge and unrelated desktop dependency upgrades. No desktop build-system replacement. No prototype APK in the ordinary public release asset set without separate scope/authorization.

## 3. Desktop touch and scroll contract

### One input owner

Add a small testable pointer sample/gesture policy, preferably `src/touch_input.[ch]`, and integrate it in `input_ui.inc` before screen handlers. Keep `PointerTarget` action/generation/attempt keys authoritative. A sample needs source (mouse/touch), down/move/up/cancel, position, timestamp and touch device/finger identity; it is not a public framework. Mouse and touch share semantic activation helpers, not synthetic SDL events pushed back onto the queue. Preserve legacy mouse exceptions explicitly.

Before SDL initialization disable touch-to-mouse and mouse-to-touch synthesis when native touch is enabled; additionally ignore SDL_TOUCH_MOUSEID mouse events and SDL_MOUSE_TOUCHID finger events. Do not discard actual mice or pen-generated real pointer input. Retain keyboard and wheel. Track one owner `(touchId, fingerId)` and window. Additional fingers cannot take over or activate anything; after owner release, still-held fingers need a fresh down to become owners. A real mouse down cancels the active touch gesture before it can establish mouse capture; stale touch releases are ignored. No per-motion allocation.

Map once into the geometry's logical coordinate space. In the selected SDL2 renderer, logical-size event filtering already adjusts normalized finger coordinates to its viewport; multiply the delivered normalized coordinates by logical width/height, validate finite values and window ID, and do not apply a second physical-to-logical transform. Assert corners, boundaries, HiDPI and resize in integration tests. Motion deltas come from consecutive mapped positions, not unadjusted tfinger.dx/dy. Never clamp an out-of-surface press into a valid control.

Buttons arm on down and activate exactly once on valid matching up. Leaving the target cancels visually; touch moving beyond slop cancels the tap permanently even if it returns. Mouse leave/reenter behavior stays as v1.3.8. Starting at A and releasing at B cannot execute B. Touch board selection occurs on a valid tap release in the original cell; dragging over the board does not paint selections or enter notes. Mouse board down and right-click notes remain immediate. No long-press-to-right-click invention. Digits/notes use existing app actions; touch does not carry keyboard modifiers.

Use Android ViewConfiguration scaledTouchSlop converted to logical units; desktop touch defaults to 8 logical pixels, adjustable only with measured evidence. Cancel on focus/hide/minimize, lifecycle, resize/inset/density change, renderer reset, screen/modal change, disabled/reordered target, keyboard navigation, wheel, scan generation change or terminal result. Reset sliders and speaker hold state too. Preserve speaker 500ms short/long press and slider drag through explicit touch ownership; slop cancellation must not break a deliberate slider drag. No duplicate click/audio.

### Help and Saved Games gestures

Start scrolling only inside the Help body or library list, never over Back/Delete/Replay/paging or a slider. Before slop, keep a potential tap. After predominantly vertical movement exceeds slop, invalidate tap capture and own the sequence until release/cancel. No inertia, overscroll, swipe-to-delete or cross-screen gesture navigation in this release.

Help: drag content with the finger/mouse, clamp existing `help_scroll_px` to its computed maximum, preserve fixed heading/Back and current wheel/keyboard steps. Below-slop release has no new action. Add concise localized instructions.

Library: accumulate vertical displacement and step selection by whole row heights using the existing selection/ensure-visible helper (upward drag advances toward later rows). This deliberately keeps the wheel/paging selection model, not a second independent viewport. Reset the remainder on cancel and reverse direction correctly. Update preview at most once per processed event batch; do not decode a record for every motion pixel. A swipe never Load/View/Replay/Delete/Save; a tap selects its original stable attempt. Disable drag during scan/detail/empty list and cancel on rescan/reorder. Preserve visible page buttons and their boundary policy. Mouse drag over the list uses the same rule; existing click, wheel and keyboard remain.

## 4. Minimal Android host and reproducible build

Choose Gradle + CMake under `android/`, using a small Java subclass of upstream SDLActivity. Source inspection confirms SDL2 and both add-ons provide CMake targets. Reference existing C sources/generated artwork; build the game as the SDL entry shared library, without SDL_MAIN_HANDLED. Do not copy/fork the engine or move desktop Makefile to CMake. Keep upstream Java host and native SDL from the same pinned revision. Any ndk-build fallback requires a concrete failed CMake integration and documented maintenance advantage, not preference churn.

Starting build selection (implementation must lock exact immutable revisions/checksums before executing downloaded inputs): SDL 2.32.10, SDL_ttf 2.24.0, SDL_mixer 2.8.1; AGP 8.11.1, Gradle 8.13, JDK 17; compileSdk/targetSdk 36; SDK Build Tools 35.0.0; NDK r28c (`28.2.13676358`); SDK CMake 3.22.1. These are a concrete build starting point, not a claim that this combination was compiled here or that these are the latest releases. Record any necessary compatibility correction in the release owner; change the roadmap only if the architectural/support decision changes.

Build shared SDL/ttf/mixer and game libraries; use the selected ttf vendored FreeType revision, samples/install off and HarfBuzz off for the existing Latin locales. Mixer: `SDL2MIXER_VORBIS=STB`, disable external-player CMD, FLAC, GME, MOD, MP3, MIDI, OPUS and WAVPACK; retain WAV support if needed by existing effect loading. Preserve all four OGG bytes. Pin recursive dependency revisions or verified release-source archives, including embedded codec/font licenses. No arbitrary binary SDK bundles, floating branches, dynamic Gradle versions or unverified wrapper downloads. Add narrowly scoped ignores for downloaded/build outputs; do not commit them.

Prototype settings: arm64-v8a; minSdk 28; temporary application ID `org.sudokura.prototype.debug`, label `Sudokura Prototype`. This is not the final public identity or a store registration. versionName derives from src/version.h with a prototype suffix; provisional versionCode = major*10000 + minor*100 + patch (10309), bounded to two-digit minor/patch. Final production ID/versionCode policy requires confirmation before registration/distribution. Debug signing uses standard ephemeral CI tooling, never committed key material. Prototype updates across independently generated CI debug keys may not install over each other: retain and test same-key local/CI rebuild pairs for upgrade testing; do not instruct uninstalling the only copy of progress to hide this limitation.

No INTERNET, broad storage, microphone, contacts or notification permission. `allowBackup=false`, legacy full-backup exclusion and Android 12+ cloud/device-transfer rules excluding the entire app data tree; verify merged manifest/rules and document OEM transfer limitations. No export/import or backup promises. Future public backup policy is a separate validated decision.

Use one `android/README.md` for actual build/device procedure and dependency lock ownership when implemented. A dedicated Android preview workflow is justified because none exists: pinned checkout/setup actions, source asset generation, locked dependencies, assembleDebug, native/manifest/asset audit and upload as CI artifact only. Trigger on relevant source/build changes and manual exact-ref builds; no publication permissions. Output APK SHA-256, source SHA, SDK/NDK/AGP/Gradle/JDK/dependency versions, ABI/library inventory and sizes. Keep desktop release-bundle validation and its six public files unchanged. CI retention is not durable release evidence: persist the relevant hashes/results in the release continuity and canonical development record before artifacts expire.

## 5. Resources, viewport, lifecycle and navigation

### Assets and storage

Package DejaVuSans.ttf at the APK asset root so the SDL-backed font path resolves without filesystem font probing; add an explicit Android-first candidate if needed. Keep the existing TTF_OpenFont path where it works; use RWops only if the actual probe requires it. Reopen fonts on density/resource reset. Put OGGs under `assets/audio/` relative to the asset root, matching the current fallback. Generate artwork/icons from the two canonical masters; no new source branding. Carry font, music, SDL and transitive notices in the package. Missing audio is nonfatal; missing mandatory font is a visible startup failure, not silent substitution.

Use SDL_GetPrefPath and current writer lock/atomic write/readback/recovery paths in app-private storage. Preserve profile/container/session/game versions, 16KiB/8KiB bounds, migration sources and receipts. Compare encoded identities across engines using synthetic fixtures, not user profiles. Verify same-app update, failed writes, previous-copy recovery and no resurrection of deleted records. No parallel Java preferences/save implementation.

### Mobile geometry

Use an inset-aware SDL surface: the thin Java host applies current status/navigation/caption/cutout insets to the surface bounds, and passes actual density/usable dimensions through a small metrics seam. Do not also subtract these insets in native geometry. Convert surface dimensions to logical dp for Android only; desktop logical pixels and restored-window preferences remain unchanged. Recompute on resize/orientation/density/inset changes, invalidate presses and rebuild fonts/textures as needed. Do not force desktop minimum-size normalization or SDL_SetWindowPosition/Size on Android.

Add a mobile geometry option consumed by rendering and all hit-testing. Keep Menu/Pause/Save/More and Undo/Redo/Clear/Notes reachable, and use a two-row 1–5 / 6–9 palette on narrow phones so digit controls can be at least 48x48dp. More keeps its pause/concealment/focus behavior. Give action buttons and list rows nonoverlapping 48dp targets; do not satisfy size by overlapping neighboring targets. Preserve readable status/Retry and complete HUD information across all languages.

Prototype portrait target: usable 360x600dp and larger; fit a square board of at least 270dp at that minimum, growing with available space. This mobile minimum does not lower v1.3.8 desktop's 288px board at 360x640. Nine 48dp cells need 432dp before margins, so the prototype cannot honestly claim every board cell meets 48dp on a narrow phone. Record cell size and accuracy/comfort; do not add zoom preemptively or claim accessibility compliance. If essential controls/text cannot fit, stop for a bounded layout adjustment rather than shrinking fonts/overlapping controls.

Test rotation/resize before the first prototype gate. Preferred behavior is playable landscape; if a very short surface cannot satisfy minimum layout, a concealed, paused, localized rotate/enlarge message with safe Back is an explicit prototype-only limitation. Preserve the live attempt and dirty state. This cannot pass functional parity/publicability and must be tracked for v1.4.0. Secondary Settings/About layout limitations may be recorded; broken main play/save/reopen, unreachable exit/recovery, or concealed data-loss errors are not permitted prototype limitations.

### Lifecycle first, on the owner thread

Introduce one small lifecycle dispatch before pointer/audio/Settings/More/screen consumption. Use current SDL_APP_WILLENTERBACKGROUND/DIDENTERBACKGROUND/WILLENTERFOREGROUND/DIDENTERFOREGROUND, terminating/low-memory and renderer-reset events. Keep all game/save mutation on the existing native owner thread. Do not save concurrently from JNI callbacks/event watches.

Retain SDL2's default blocking-on-pause behavior initially. Inspection of the selected Android pump shows it delivers background events before blocking; drain/handle them and checkpoint before the next pump. Once WILLENTERBACKGROUND is consumed, perform no renderer calls until DIDENTERFOREGROUND. Defer resource rebuild until foreground; do not draw from generation or dialogs while suspended.

On first background transition: settle elapsed time at the event boundary, acquire focus pause without clearing other reasons, cancel every transient gesture/modal-owned pointer state, stage/checkpoint live progress and dirty preferences using existing checked helpers, silence audio independently of whether a session exists, and stop rendering/scans/generation. Suppress duplicate writes for repeated background notifications. Keep failure/dirty state; no background modal dialog, discard or false Saved status. On foreground, refresh metrics/resources, report any failed checkpoint with Retry and retain focus pause until explicit Resume. Audio foreground gating must not override manual/focus pause or restart jingles spuriously; Home audio may resume its prior context. This requires an app-suspended gate in audio sync, since current pause bits alone do not cover Home.

Generation callback must process the narrow lifecycle/cancel set before rendering. Cancel the in-progress candidate on background/Back; retain the previous valid session/identity, no fallback puzzle or partial publication. Drain lifecycle during startup/migration/recovery and library scans; native dialogs must not swallow it or render after surface loss. Keep migration transactions intact if stopping. Test a queued lifecycle event during each path, not just normal play. Ordinary SDL_QUIT still uses existing checked exit; Android process kill may deliver no Quit.

Existing autosave policy is 750ms quiet / 5000ms maximum dirty interval while execution is available, with an explicit background checkpoint. This is not a guarantee against an OS kill before acknowledgement. After successful Save/checkpoint, the same or newer acknowledged revision must reopen; after an unacknowledged abrupt kill, recover a valid previous state with no invented promise of the last input.

### Back and URLs

Translate Android Back (`SDLK_AC_BACK`/current platform Back callback) into one application command, not a blind Activity.finish. Consume repeat/up so a gesture triggers once. Priority: cancel/close native confirmation without accepting it; dismiss transient popup/More/Settings; close library detail, then library/Help/About to prior context; cancel generation/scan; gameplay uses checked Menu/Home; Home uses checked exit/finish. Do not clear unrelated pause reasons or bypass Retry/Back save gates. Verify gesture navigation and three-button navigation on a current target-36 device; deprecated key delivery alone is not proof of modern Back support. If required, add only the thin Java Back-to-SDL bridge, never two parallel dispatches.

On Android use SDL_OpenURL after the existing allowlist, with normal failure feedback if no handler. Desktop launcher/environment isolation stays unchanged. External browser navigation invokes the same lifecycle checkpoint; offline gameplay does not require the URL to succeed.
