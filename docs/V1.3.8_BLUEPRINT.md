# Sudokura v1.3.8 implementation blueprint

Status: Phase 0 specification; no implementation included.
Baseline: `483edc8ea3f93698f7781e7fe933a9d996f93fdf`.
Target branch: `release/1.3.8`.
Roadmap owner: [Android release plan](ANDROID_RELEASE_PLAN.md).
Repository-local instructions: [AGENTS.md](../AGENTS.md).
Inspection date: 2026-10-26.

## 1. Release contract

Make desktop play more comfortable in narrow windows, make ordinary button actions cancellable before release, and make every retained game reachable using ordinary pointer buttons. Repair the observed incremental-build dependency defect. Prepare only the shared interaction/layout seams needed for these changes.

This blueprint does not authorize implementation by itself. Phase 1 starts only after explicit adoption/implementation authority. No merge, tag, release, deployment, destructive operation or credential/permission change is included.

### Preserve

- C11, SDL2/ttf/mixer, current visual identity and canonical artwork.
- Keyboard shortcuts, event-local modifiers, right-click note behavior, all game modes/difficulties, Daily local-date semantics, deterministic revision 3 and revision-2 reconstruction.
- Exact puzzle identity on Restart/Retry; stable attempt identity on repeated Save; fresh identity on New/Replay; original Daily independent of practice replay.
- Normal/Daily slots, completed library beyond 128 summaries, checked writes, readback, recovery, incompatible-format handling, immutable migration sources and deletion receipts.
- EN/ES/CA, themes, reduced motion, optional audio, neutral Classic/Daily feedback, offline operation.
- Independent pause reasons, terminal-event ordering, save-error navigation gates and explicit focus-pause resume.
- Existing desktop package architecture and public artifact contract.

### Exclude

Android host/SDK/APK, direct SDL_FINGER support, swipe gestures, lifecycle bridge, app ID/signing work, store publication, new persistence formats, changed generator revision, database/cloud sync, full screen-reader bridge, new modes, large file moves, generic widget/event framework, dependency upgrades without demonstrated need. Do not lower existing supported desktop minima or claim phone-ready accessibility.

## 2. Repository understanding and coverage

The baseline tree contains 20 C implementation modules and nine SDL presentation fragments. Core rules/generation and the human evaluator live in game/human; app and app_clock own actions and time; input maps keyboard/mouse policy; geometry owns common layout; profile/session/store_io and game_library/codec/migration own durable state. The single SDL translation unit includes runtime, font discovery, board rendering, screens, ui_present, games_ui, audio/input adapters and the main loop. It already has useful seams; no engine extraction is necessary.

Coverage included the complete tree inventory, AGENTS, README/changelog/current reporting and release documentation, all module interfaces and targeted implementation paths for generation/actions, persistence/migration, input/layout, font/audio/resources, external URLs, event loop, library navigation, tests, Makefile and CI/package/release machinery. Packaging was inspected for version derivation, asset/dependency inclusion, audits, pinned downloads and draft-only release behavior. The canonical v1.3.7 screenshot's actual bytes were visually inspected.

This is a repository-wide planning review with targeted deep reads, not a claim that every line was independently audited. Historical implementation/release documents were treated as history, not revalidated specifications. Binary audio was inventoried with its provenance, not listened to; historical screenshots were not reapproved. Windows/macOS packages were not executed. No live SDL application, physical touch device or Android prototype was available in this Phase 0. Native UI-fit, audio and package acceptance remain implementation gates.

The v1.3.7 tag resolves to the same commit as main. Latest release publication is 2026-10-15T19:08:15Z. Only main and no open PRs were observed before planning. No v1.3.8 numbering conflict was found. The AGENTS v1.3.7 target is baseline context; update it narrowly during Phase 1 for the explicitly requested v1.3.8.

## 4. Implementation specification

### A. Compact gameplay layout

Keep the existing regular and XL desktop presentation. Change the narrow portrait branch (width < 640) through shared geometry, not by moving pixels only in the renderer.

At 360×640 use a board of at least 288×288 (32px cells), compared with the measured 243×243 baseline. At 390×844 and 412×915 do not reduce the baseline boards (369 and 396 respectively). The board remains square and divisible by nine. Show the complete proportional wordmark without clipping.

Keep these directly available during play: Menu, Pause, Save, digits 1–9, Notes, Clear, Undo and Redo. Combine the frequent edit controls in one row and retain the compact single-row digit palette when necessary; this release targets desktop pointer use, not a 48dp phone guarantee. Frequent non-digit controls should be at least 36 logical pixels high and digits at least 40 high in the 360×640 target, with distinct nonoverlapping hit targets. The palette's narrow digit widths are an explicit mobile follow-up.

Move infrequent Restart, Hint, Verify, Settings and Help into a clearly labeled More panel only in the narrow layout. Do not repurpose Menu or remove existing keyboard shortcuts. Keep Save visually prominent. Include About through the existing navigation. The full HUD still communicates mode/difficulty, time, applicable strikes/time limit and assistance state; compact formatting may omit decorative labels, not gameplay information. The status area retains save failure/Retry visibility and progress.

A feasible 640px vertical budget is a small proportional wordmark/header, a 36px Menu/Pause/Save/More row, compact HUD, 288px board, a 36px edit row, 40px digit palette and status plus modest gaps. The implementation must calculate the actual rectangles and text fit; this budget is not permission to clip longer translations. Use more space when available rather than fixing the board to the minimum.

More is transient presentation state, not a saved preference. Opening it owns a modal pause only if it newly acquires that reason; closing releases only its own reason. It consumes pointer input inside and outside (outside click closes without click-through), supports Tab/Shift+Tab and Enter/Space, Escape closes it and restores focus to More. Resize/screen transition closes it and cancels captured presses. Do not expose a running Time Attack board behind a paused overlay: use the existing concealment policy or cover the board while the panel owns the pause. Dispatch selected actions through existing checked helpers and save/confirmation paths. Closing must not clear a pre-existing manual/focus/result pause.

Update geometry tests to assert semantic controls and fit rather than obsolete full-width action-row positions. Existing enum aliases may remain only where they still mean the same thing. Prefer a small gameplay-controls geometry structure used by both rendering and hit-testing over extending the current mismatch where PLAY_ACTION_PAUSE is subdivided into Undo/Redo and PLAY_ACTION_RESTART into Clear/Restart. Do not rename/rewrite every UI screen.

Affected owners: src/geometry.[ch], src/sudokura_sdl/ui_present.inc, 03_board_render.inc and 05_main.inc; input_ui.inc for overlay routing; i18n.[ch] for new labels and Help. Add only the narrow declarations/helpers needed.

### B. Cancellable primary-pointer activation

Introduce a small testable capture policy in input.[ch] or a focused header beside button_feedback.h. Track pressed action identity, screen/modal generation and original rectangle. A left-button down on an enabled ordinary control arms it and shows pressed feedback. Execute exactly once on matching left-button up inside the same valid control. Release elsewhere cancels. Crossing to another control must never activate that second control; leaving and returning to the original before release may activate it.

Cancel on window focus loss/hide/minimize, resize, screen/overlay change, terminal transition, lost mouse capture and disabled/disappeared target. A release without a preceding valid press does nothing. If SDL_CaptureMouse is available, use it to receive releases outside the window, but fail safely when capture is unavailable. No per-click allocation or persistent schema fields.

Apply this consistently to Home buttons/segments, gameplay actions/digits, More, library row selection/actions/paging, Settings toggles/+/-/Back, Help/About links/Back, and result/pause controls. Native message boxes retain platform behavior and confirmation gates.

Exceptions are deliberate: board-cell selection remains immediate on press for desktop speed; keyboard actions retain existing keydown/repeat policy; right-click notes remain unchanged; sliders start drag on down and update while dragged, ending/cancelling safely; the existing speaker short/long press keeps its 500ms contract and is not dispatched twice. No new generic gesture system or SDL_FINGER handling in this release.

Resolve target identity before dispatch instead of replaying a synthetic mouse-down into arbitrary current-screen handlers. A callback that opens a dialog or changes screen invalidates the old capture before dispatch. Give normal click feedback only for the executed action; a cancelled press must not modify preferences, board, save state or history.

### C. Library paging without a wheel

Add visible Previous page / Next page controls and a localized range/count indication adjacent to the list. Reserve their rectangles in GamesBrowserLayout and use them for rendering, focus and hit-testing. Keep Load/View/Replay/Delete/Back placement and confirmation semantics. Page controls must not overlap a partial row or shrink the compact preview below its current usable bounds.

Use the current visible-row count as page step, clamped to 0..count-1. A page action selects the clamped next index and calls the existing selection/preview/ensure-visible path, just as PageUp/PageDown do; this avoids adding a second selection model. Disable Previous at the beginning, Next at the end, both during scan, when empty, or when an exact detail view is open. Single-page libraries must not show an enabled useless action. Retain wheel and keyboard behavior. Tab order includes enabled page actions and returns predictably after Back/detail.

A press must bind the intended record ID, not merely a row index that might change during rescan; cancel if ordering/layout changes before release. Page navigation and row selection must not mutate records, create attempts or trigger Delete/Replay automatically. Keep scans incremental, selected preview loading bounded, and corruption/future-format rows visible under existing policy.

Affected owners: games_ui.inc, input policy, i18n.[ch], tests for paging boundaries and UI diagnostic scenarios. Do not add filters/search/tags or a separate library database.

### D. Build and focused housekeeping

Declare games_ui.inc in the sudokura prerequisites; keep existing build conventions. Check the full set of current .inc includes against prerequisites so another omitted include is not overlooked. Demonstrate that make -n -W src/sudokura_sdl/games_ui.inc sudokura schedules a rebuild after a successful up-to-date build.

Add exact ignored executable paths for tests/test_game_library and tests/test_game_migration. Existing make clean already names both. Correct test-owned leftover cleanup only after verifying ownership; no git clean, wildcard profile deletion or user-data migration. Do not commit test outputs.

In Phase 1 update src/version.h to 1.3.8 and the version-specific AGENTS target. During release preparation update existing README/changelog/gallery/reporting owners and create concise RELEASE_NOTES_1.3.8.md. Do not mark Android supported or replace historical screenshots with diagnostics. Keep the planning docs separate from release publication copy.

3. **Compact composition and library navigation.** Implement A/C against the shared targets; add localized strings, More focus/pause handling, paging tests and diagnostic cases. Keep all modes and regular/XL layout intact.
4. **Integrated validation and measured review.** Execute the existing checks below once on the coherent candidate; rerun only affected checks after corrections. Review screenshots from actual candidate bytes across modes/languages/themes and test realistic input sequences. No passing unit test substitutes for interaction or visual review.
5. **Release preparation handoff.** Verify exact package outputs, public version/docs consistency and canonical imagery according to current AGENTS and active workstream requirements. Record remaining manual/device evidence honestly. Stop before merge/publication unless separately authorized.

## 7. Efficiency and risks

The unchanged baseline's library test measured 40 hot checkpoints in 144.42ms and a 1000-entry metadata scan in 13.84ms wall time on this host. These are illustrative single-host measurements, not budgets for phones. v1.3.7 published package sizes are approximately 12.28MB AppImage, 7.71MB portable EXE, 9.64MB installer and 6.99MB macOS DMG; compare like-for-like candidate artifacts rather than raw executable size.

No new runtime dependency or bundled media is expected in 1.3.8. Pointer capture is constant-size state, paging reuses the catalogue, and the current dirty-render/wait loop stays. Run the existing desktop benchmark on baseline and candidate under the same host/renderer when the SDL environment is available; record input-to-present, idle CPU, startup, RSS, save and generation figures. Investigate reproducible regressions, especially retained per-action allocations, unbounded caches or a new idle redraw loop. Do not set an arbitrary cross-hardware latency promise.

Main risks: missed legacy event branch still firing on down; stale row/action after rescan; More stealing a pause reason; translated text not fitting compact controls; changing regular desktop geometry unnecessarily. Each has an explicit acceptance row above. If the compact target cannot be met without hiding essential information, report the concrete layout conflict before relaxing the target; do not silently shrink text below current readable minima.
