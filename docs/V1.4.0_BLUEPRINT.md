# Sudokura v1.4.0 implementation blueprint

Status: Phase 0 planning complete; implementation NOT STARTED. No Android publicability claimed.
Base: f7e8acb4a2a3fdfed9267d8862e8b30057710d7a (published v1.3.9).
Branch: release/1.4.0.
Owners: [development](DEVELOPMENT.md), [Android roadmap](ANDROID_RELEASE_PLAN.md).
The roadmap's full preservation and publicability requirements are mandatory, not replaced by this document.

## Outcome and scope

Deliver reliable interruption/recovery and readable, navigable compact interfaces to desktop users, while completing Android functional parity and preparing the first stable direct APK. Public Android remains preferred here and required by v1.5.0; do not silently split this into a desktop-only release or waive a device gate. A genuine conflict requires a maintainer decision with named blockers.

Keep C11/SDL2/ttf/mixer, existing Makefile and shared engine. Preserve all modes/difficulties, gen3 and rev2 reconstruction, Daily local-date identity, normal/Daily independence, attempt identity, Restart/Retry, edits/Undo/Redo, hints and Classic/Daily hidden-solution neutrality, durable library/receipts/recovery, locales/themes/reduced motion/audio optional/offline. No codec or generator revision change. No cloud, accounts, import/export, new modes, SDL3 or toolkit rewrite.

Concrete desktop benefit: consistent cancellable confirmations and persistent save-failure recovery, robust renderer recovery without leaving an apparently interactive blank window, and compact dialog/auxiliary-screen layouts shared with mobile. These are useful even without Android publication.

## 1. Shared interruption and modal recovery

Owners: 04_screens.inc dialog wrappers, 05_main.inc action callers/generation/main loop, input_ui.inc global preparation, 01_runtime.inc persistence, audio_ui.inc, app_clock/save_policy; tests in existing clock/app/live-save/input integration owners.

Use one small active-modal record: kind, localized title/body/button keys, caller continuation/action, selected stable attempt ID plus revision/generation, focus and owned pause reason. Do not build a general UI framework or move all presentation files. Convert call sites to request/result continuation rather than nesting another polling loop or launching another thread.

Cancellation is default for destructive operations; Escape/Back closes only the top modal. Enter must never newly accept Delete/Discard by default. Capture stable record identity, revalidate before completion, and cancel stale actions after rescan/navigation/rotation. The modal owns PAUSE_MODAL only if it acquired it; never clear manual/focus/Home/result reasons. Game content remains concealed while paused.

Every modal frame uses current geometry and the main event pump. Lifecycle events run before modal/input dispatch. Background cancels transient presses, freezes time, checkpoints on the native owner, silences audio and suspends render/scan work. Cancellation of generation retains the previous valid session. On foreground retain explicit Resume, rebuild resources, then expose recovery UI. Native fatal bootstrap dialogs may remain only before SDL resources/game state exist.

A failed checkpoint remains dirty and visible through a persistent recoverable status, with Retry and safe Back. Reuse existing checked save gates, retry timing and prior-copy semantics; do not replace them with a second save system. Save is acknowledged only under the existing durable verification contract. No promise to save the last unacknowledged input before abrupt OS kill (750ms quiet/5000ms dirty window remains).

Track renderer availability separately from foreground state. Failed refresh/rebuild cannot re-enable ordinary gameplay/render calls against invalid resources. Retry once on a subsequent legitimate restore/reset or explicit Retry; avoid hot loops. Offer a safe exit/checkpoint path without discarding the live session. Preserve optional audio failure and reconnect semantics.

Acceptance: queued background/foreground while each modal is open; Delete/Replay identity changes; failed storage followed by retry; overlapping pause reasons; focus loss during generation; renderer failure injected through a narrow test seam; no draw while suspended and no duplicate commits. Test actual SDL dispatch, not only the pure lifecycle reducer.

## 2. Responsive parity and accessibility

Owners: geometry.[ch], 03_board_render.inc, ui_present.inc, 04_screens.inc, games_ui.inc, input_ui.inc, i18n.[ch], Android activity.

Retain existing desktop 360x640/640x480, regular and XL behavior. Android baseline portrait remains 360x600 usable dp; add a landscape composition targeting 600x360 usable dp: square board at least 270dp on the left, controls/status in a right panel; secondary actions in More, digit palette in a compact grid with 48dp action targets. Do not force a portrait geometry or normalize Android window size to desktop bounds. Fit all modes' HUD information without hiding errors. Portrait/sufficient landscape must be playable; smaller split windows may show a truthful paused minimum-size state, never qualify that fallback as supported landscape parity.

Reuse one geometry for render, touch, focus and semantic bounds. Insets already reduce SDL surface in Java; do not subtract twice. Recompute and cancel capture on density/size/insets changes. Short Home/settings/help/library/dialog content may scroll inside a bounded body with persistent navigation; preserve visible paging and non-gesture controls. Do not shrink text until unreadable to pass fit checks. Modal layout handles EN/ES/CA and large fonts with wrapping/scrolling. No inertial gesture framework.

Early in this unit record TalkBack behavior on the existing build. Implement a bounded AccessibilityNodeProvider bridge for visible actionable controls and 81 board cells using immutable native snapshots. Stable node IDs, screen generation, labels/state/enabled/actions/bounds; publish only on material change, not every frame. Java callbacks enqueue semantic commands to SDL; never mutate game/save on the UI thread. Native dispatcher revalidates generation, enabled state, stable attempt identity and pause state. Use current action helpers, not coordinate spoofing.

Cells describe row/column, given or entered value, notes, selection and visible conflicts only. Never expose solution or hidden correctness in Classic/Daily. Paused/concealed boards have no readable cell values. Announce Save failure/success and screen changes without timer spam. Keep accessibility focus separate from edit selection and invalidate stale nodes after modal/rotation. Support traversal, activation and scroll for Home/settings/help/library/More/results/dialogs. Do not claim TalkBack parity before a complete user journey passes.

Acceptance matrix: portrait 360x600/390x844/412x915; landscape 600x360/800x480; desktop minimum/regular/XL; both themes/three languages/1x–3x density; asymmetric insets; keyboard/mouse/touch; modal and storage errors; mixed library entries and large catalogue. Device test verifies bounds and useful targets. Board cells cannot all be 48dp on a narrow phone: measure and disclose this honestly.

## 3. Android identity, packaging and early device proof

Retain pinned toolchain/dependencies initially: minSdk28, arm64-v8a, target/compile36; no speculative older-device fallback or broad upgrades. Any dependency adjustment requires a concrete compatibility/license/security reason and lock/audit update. x86_64 is test-only if an emulator needs it, not an extra public ABI by default.

Proposed production application ID: org.cajapersonal.sudokura, subject to explicit maintainer confirmation before freezing public identity/signing. Keep org.sudokura.prototype.debug separate. Do not register anything during implementation without authority. Preserve source-version derivation; release versionName 1.4.0, versionCode 10400 under checked major*10000+minor*100+patch bounds. Debug variant keeps a suffix and cannot masquerade as production.

Production backup policy: keep cloud/device-transfer excluded for this release, verify merged manifest and actual supported behavior, document that uninstall clears local progress. No migration guarantee from the separate prototype. Preserve the old installation; transfer is separately scoped if the maintainer needs it. Same production ID/certificate updates must preserve the complete profile/library/receipts.

Extend existing preview/audit owners, not a parallel pipeline: branch-aware preview, version-derived expectations, explicit debug/release variant, manifest/permissions/native closure/assets/notices checks. Audit all packaged native libraries and zip alignment. Retain no unnecessary permissions. Include font/FreeType and embedded codec/source licenses; generate a full dependency inventory from actual build inputs.

Build unsigned release candidates before requesting signing authority. Production signing/key generation/custody is a separate secure authorized step; no secrets in repo, Issues or logs, no fallback to debug signing. Final distributable name: Sudokura-1.4.0-Android-arm64.apk, integrated with existing checksums/Build-Info source provenance. Keep the four desktop applications and their audits unchanged. F-Droid source-build/metadata eligibility is planned; submission/acceptance is external. Play/AAB publication is optional, not required to ship the direct APK.

Before substantial final polish, build one exact-head preview and test on a real ARM64 phone. Record device/API/ABI/density/insets/navigation, APK digest/source and results. Reuse deterministic fixture output to compare complete original+solution for seed/difficulty/revision and Daily against desktop, executed on ARM64. Test acknowledged Save followed by actual process termination/relaunch, not just Activity recreation; isolate disposable data. Include notes/Undo/Redo/revision/attempt and deletion receipts. Verify modern Back, lock/Home, all modes, dialogs, generation, scans, startup and audio reconnect.

16 KiB gate: all ELF PT_LOAD and APK alignment plus execution on an actual 16 KiB emulator/device, recording page size and compatibility mode. Structural PASS alone never suffices. Measure package/installed size, five cold/warm starts, twenty input samples, generation per difficulty, save latency, RSS and 60s idle/background CPU. Preserve dirty/wait rendering and bounded caches; investigate reproducible regressions against v1.3.9 under comparable conditions. No invented universal latency budget.

## 4. Acceptance and release handoff

Run existing core/UI/SDL smoke, sanitizers, generator quality, i18n/contrast/text fit and package matrix on the implementation candidate. Add only focused regression tests for changed behavior. Verify desktop fixed-seed equivalence to v1.3.9, storage faults/migration/deletion recovery and exact library behavior. New semantic actions must pass the same gameplay/persistence gates as pointer/keyboard.

Public Android requires all roadmap parity/device/16 KiB/signing/upgrade/privacy/license gates. Prepare same-key clean install and upgrade pair, verify complete save/library retention and Obtainium discovery/update without uninstall. An unavailable signing/device acceptance step is a named release blocker, not a reason to mark PASS. If v1.4.0 cannot safely achieve publicability, present exact remaining work for a maintainer decision before changing release scope; no automatic v1.5.0 jump.

Prepare README, CHANGELOG, release notes, reporting/migration guidance, build instructions and truthful localized store metadata. Preserve historical images; obtain accepted current actual desktop screenshot and genuine Android captures. Review exact candidate image bytes and final public copy with the maintainer before recommending merge. F-Droid/Play availability must not be claimed before actual acceptance. No store submission, signing, merge, tag or publication is authorized by this plan.

After separately authorized publication, verify public release/tag/main/source, workflows/assets and outstanding Android gates; synchronize the transversal masterplan before closing release continuity. Phase 0 completion is not release completion.
