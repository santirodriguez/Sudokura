# Sudokura v1.1.0 implementation record

This document records the scope completed for Sudokura v1.1.0. It is retained as a technical implementation summary; the user-facing release description lives in [`RELEASE_NOTES_1.1.0.md`](RELEASE_NOTES_1.1.0.md).

## Delivered architecture and tests

- The application remains lightweight C11 with SDL2 and SDL2_ttf.
- Game rules, localization, and responsive geometry are separated into testable modules without changing the three original game modes.
- Deterministic tests cover solved-board validity, puzzle uniqueness, clue and fixed-cell behavior, placement and clearing, notes, hints, conflicts, solved state, Classic, Strikes, Time Attack, localization bounds, and responsive geometry.
- UI text-fit tests use real SDL_ttf measurements in English, Español, and Català.
- Normal CI compiles with warnings as errors on Linux and runs the complete Windows package path under MinGW/MSYS2.

## Responsive interface

- Desktop content is centered and bounded instead of stretching indefinitely on large or ultrawide displays.
- The number palette uses a compact 3×3 layout and actions use responsive grids.
- Native stacked layouts cover 360×640, 390×844, and 412×915 portrait viewports.
- The same geometry drives rendering and pointer hit-testing.
- Title, game, help, about, confirmation, result, and pause states are included in layout validation.
- Typography uses a reusable multi-size cache and fits translated strings to their containers.

## Localization

Sudokura includes complete internal translation tables for:

- English
- Español — natural Argentine Spanish, displayed as `Español`
- Català

Menus, modes, HUD, controls, help, about, dialogs, errors, results, and messages use the translation layer. A visible segmented language selector is available by pointer and keyboard.

## Branding and assets

Five new logo artwork files were added under `assets/branding/source/` for v1.1.0.

- `Sudokura03.png` is used for README and release presentation.
- `Sudokura02.png` supplies the compact in-app wordmark.
- `Sudokura05.png` supplies reproducible Linux, Windows, macOS, and SDL window icons.

The source artwork is preserved as uploaded. Asset generation validates eight PNG sizes, a multi-size ICO, ICNS, embedded RGBA window-icon data, and the in-app wordmark without adding SDL_image.

## Desktop packages

### Linux

- Portable x86_64 AppImage.
- Real desktop icon and entry.
- Bundled DejaVu Sans fallback font and license.
- Binary and AppImage smoke tests, dependency report, inventory, checksum, and archive-size reporting.

### Windows

- Portable x86_64 ZIP with GUI executable and embedded ICO.
- Recursive PE import closure copies all required non-system DLLs.
- Direct imports are validated independently of `ntldd` output formatting.
- The packaged directory and the extracted ZIP both run smoke tests with a clean `PATH`.
- DejaVu Sans and its license, inventory, dependency report, checksum, and archive integrity checks are included.

### macOS

- Separate unsigned x86_64 and arm64 ZIPs containing a real `Sudokura.app`.
- SDL2, SDL2_ttf, transitive non-system dylibs, icon, fallback font, and license are bundled.
- Install names use bundle-relative paths and validation rejects Homebrew or runner-local paths.
- Architecture, inventory, dependency, smoke-test, ZIP-integrity, checksum, and size reports are generated.
- The final packages were not launched manually on real Mac hardware and are distributed with a request for user feedback.

## Release process

- Manual package previews cannot publish a release.
- The exact `v1.1.0` tag builds all four packages and a combined `SHA256SUMS.txt`.
- Only the four runtime packages and the combined checksum file are attached publicly; diagnostic inventories and dependency reports remain workflow artifacts.

## Validation status

- Linux AppImage: automated validation complete and manually tested.
- Windows ZIP: automated validation complete and manually tested.
- macOS x86_64 and arm64: automated architecture, dependency, resource, ZIP-integrity, and checksum validation complete; no manual real-Mac launch was performed.
- Generated UI review set: 40 exact-size screenshots across ten viewports and four screens, with automated completeness and blank-frame validation.
- Documentation screenshots: current v1.1.0 and historical v1 images archived and linked.

## Out of scope for v1.1.0

- Browser/WebAssembly packaging.
- Framework or language migration.
- New game modes or gameplay redesign.
