# Sudokura v1.2.0 implementation record

This document records the implemented v1.2.0 architecture and validation design. The user-facing summary lives in [`RELEASE_NOTES_1.2.0.md`](RELEASE_NOTES_1.2.0.md).

## Gameplay core

- The application remains C11 with SDL2 and SDL2_ttf.
- Puzzle generation uses a fixed-width deterministic PRNG rather than the C library `rand()` implementation.
- Easy, Medium, and Hard generation is deterministic by seed, difficulty, and generator revision.
- Clue removal retains only uniquely solvable puzzles, and deterministic scoring separates the supported difficulty bands.
- Daily Puzzle maps a validated Gregorian date to a deterministic seed and uses Classic · Medium for v1.2.
- Progress counts originally empty cells that currently match the solution; wrong entries do not advance progress and hinted cells do.
- Hinted cells are locked, and normal input, notes, clear, and Strict-mode rejection flow through one central player-input API.
- Restart restores the exact initial puzzle and clears player progress, notes, and hint markers without changing puzzle identity.

## Session persistence

- Session state and preferences are persisted independently.
- The binary format is explicitly versioned and serialized field-by-field rather than writing raw C structs.
- Stored payloads use CRC32 plus semantic validation of board state, generator metadata, ranges, hints, fixed cells, notes, Daily identity, and result state.
- Invalid, truncated, unsupported, or tampered saves fail closed and may be quarantined for diagnosis instead of being loaded.
- Writes use a temporary file followed by replacement so an interrupted write does not intentionally overwrite the last valid state.
- Continue restores the active puzzle, player state, mode, difficulty, selection, timer, mistakes, and pause state.
- Preferences persist language, theme, Strict/Free, last mode, and last difficulty.

## Timer and pause model

- Elapsed gameplay time is accumulated using a monotonic runtime clock.
- Independent pause reasons cover manual pause, focus loss, modal screens, Home, and end state.
- Losing focus pauses and autosaves; restoring focus removes only the focus-related pause reason.
- Help and About suspend active gameplay time without incorrectly overriding an existing manual pause.
- Manual pause hides the board and blocks gameplay input until Resume.

## Responsive interface

- Home exposes segmented mode and difficulty selectors plus New Game, Continue, and Daily Puzzle.
- Language selection uses bundled USA, Argentina, and Senyera assets rendered directly from generated RGBA data; SDL_image is not required.
- The game HUD exposes mode or Daily identity, difficulty, time, errors, Strict/Free state, and mode-specific status.
- Progress is graphical, completed number-palette entries are visually reduced, and hinted cells have a distinct visual state.
- Portrait layouts use a horizontal 1–9 number palette while desktop layouts retain the compact grid treatment.
- The same geometry structures drive drawing and pointer hit-testing.
- Supported layout tests include desktop sizes from 640×480 to 3440×1440 and portrait sizes 360×640, 390×844, and 412×915.

## Localization and branding

- User-visible interface text is routed through translation tables for English, Español, and Català.
- Maintained Spanish strings use general Spanish forms.
- `sudokura-head.png` is the primary project and in-app identity.
- Source branding variants are preserved under `assets/branding/source/` and `assets/branding/source-packed/`; previous v1.1 artwork is retained under `assets/branding/history/v1.1/`.
- Language flags and their upstream MIT provenance are vendored under `assets/flags/` for fully offline runtime use.
- Derived platform icons, the SDL window icon, the embedded head, and embedded flags are generated reproducibly without SDL_image.

## Version and package metadata

- `version.h` numeric major/minor/patch macros are the repository source of truth for v1.2.0.
- `scripts/version.sh` exposes that source version to packaging and CI.
- Package scripts reject an externally supplied version that disagrees with the source.
- Windows version resources use the numeric source macros and string version.
- The macOS bundle renders its Info.plist version fields from the source version during packaging.

## Desktop packages

### Linux

- Portable x86_64 AppImage with application icon, DejaVu Sans fallback font, and font license.
- Raw AppDir binary and final AppImage receive smoke tests.
- Package inventory, dependency report, checksum, and size are generated.
- The `linuxdeploy` executable is fetched by an immutable GitHub release asset ID and verified against the upstream-published SHA-256 before use.

### Windows

- Portable x86_64 ZIP with a GUI executable, embedded icon/version resource, fallback font, and license.
- Recursive PE import closure copies required non-system DLLs and independently rejects unresolved direct imports.
- The packaged directory and extracted ZIP receive smoke tests with a clean runtime search path.
- Archive integrity, resource presence, inventory, dependency reports, checksum, and size are validated.

### macOS

- Separate unsigned x86_64 and arm64 ZIPs containing real `Sudokura.app` bundles.
- SDL2, SDL2_ttf, transitive non-system dylibs, icon, fallback font, and license are bundled.
- Dynamic-library install names use bundle-relative paths; validation rejects Homebrew and runner-local paths.
- Source-derived bundle version, architecture, resources, dependency closure, ZIP integrity, checksum, inventory, and headless smoke-test result are recorded.
- A real Mac launch remains a manual validation gate unless it is actually performed and reported.

## Automated validation

- Deterministic generation, uniqueness, difficulties, Daily identity, Restart, progress, hints, input behavior, conflicts, game-mode endings, localization, and responsive geometry are covered by the core suite.
- Persistence tests cover round trips, corruption, truncation, bad checksums, unsupported format versions, invalid semantic state, atomic replacement, Daily metadata, and result states.
- SDL_ttf tests measure interface text in English, Español, and Català for supported responsive tiers.
- Linux CI additionally runs AddressSanitizer and UndefinedBehaviorSanitizer against core and persistence tests.
- Diagnostic UI review renders cover ten viewports and five screens, producing 50 non-canonical BMP frames checked for exact dimensions and non-blank content.
- Linux, Windows, Intel macOS, and Apple Silicon macOS package previews are built before release publication.

## Release process

- Package previews are non-publishing and use the exact requested ref or pull-request head SHA.
- Release automation accepts tags matching `v*` but rejects a tag whose value does not match the version declared by the source.
- The workflow builds four runtime packages plus one combined `SHA256SUMS.txt`.
- Only the draft-release job receives `contents: write`; build jobs use read-only repository permissions.
- A matching release tag creates a draft release for manual review. Publishing the draft remains a separate explicit action.
- The canonical v1.2 screenshot is intentionally deferred until a real release candidate has been manually tested and the user supplies the final image.

## Out of scope for v1.2.0

- Browser/WebAssembly packaging.
- Framework or language migration.
- Online accounts or network-backed puzzle services.
- Signed or notarized macOS distribution unless those steps are explicitly added and actually performed.
