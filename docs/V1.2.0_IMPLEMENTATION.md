# Sudokura v1.2.0 implementation record

This document records the implemented v1.2.0 architecture and validation design. The user-facing summary lives in [`RELEASE_NOTES_1.2.0.md`](RELEASE_NOTES_1.2.0.md).

## Gameplay core

- The application remains C11 with SDL2, SDL2_ttf, and the deliberately approved SDL2_mixer audio layer.
- Generator revision 2 uses a fixed-width deterministic PRNG and deterministic randomized backtracking from an empty board.
- Easy, Medium, and Hard generation is deterministic by seed, difficulty, and generator revision; clue removal preserves a unique solution.
- New normal games obtain a 64-bit seed from operating-system entropy where available, with a safe fallback path.
- Daily Puzzle maps a validated Gregorian date to a deterministic seed and uses Classic · Medium for v1.2.
- `game_mode_reveals_correctness()` remains the policy boundary for hidden-solution feedback. Classic/Daily expose Sudoku-rule conflicts and neutral fill state; Strikes/Time Attack may expose correctness.
- Hinted cells remain locked; Restart restores the exact initial puzzle without changing puzzle identity.

## Session persistence

- Session state and preferences are persisted independently in explicit versioned binary containers.
- Stored payloads use CRC32 plus semantic validation of board state, generator metadata, ranges, hints, fixed cells, notes, Daily identity, and result state.
- Corrupt or tampered saves fail closed. Incompatible generator revisions are reported as incompatible rather than corrupt.
- Writes use a temporary file followed by replacement.
- Continue restores puzzle/player state, selection, timer, mistakes, mode, difficulty, pause state, and relevant preferences.
- Continue is exposed only for active sessions; completed sessions remain stored for result/Daily semantics but are not presented as resumable games.
- Replacement and Restart warnings use meaningful player progress rather than elapsed time or selection movement alone.
- Audio enable/disable plus independent Music/FX levels remain backward compatible with earlier v1.2 release-candidate preference payloads.

## Input routing

- Top-row and physical numeric-keypad digits are normalized by one explicit input-mapping helper rather than assuming SDL keypad keycodes are arithmetically contiguous around `SDLK_KP_0`.
- Physical keypad scancodes provide the stable fallback when Num Lock causes SDL to report navigation keycodes.
- In-game controls use semantic action identities for Menu, Pause, Restart, Hint, Notes, Verify, Audio, Help, and About instead of relying on overloaded positional button meanings.
- Pointer hit-testing uses the same geometry objects used for rendering.

## Timer and pause model

- Elapsed gameplay time is accumulated using a monotonic runtime clock.
- Independent pause reasons cover manual pause, focus loss, modal screens, Home, and end state.
- Losing focus pauses and autosaves; restoring focus removes only the focus-related reason.
- Help/About/Audio suspend active gameplay time without overriding an existing manual pause.
- Manual pause hides the board and blocks gameplay input until Resume.

## Audio

- SDL2_mixer is optional at runtime: initialization, device, file, or decode failure never prevents Sudokura from starting or preserving state.
- The four OGG files are MintoDog's `Cozy Puzzle Jingle & Result` tracks from OpenGameArt under CC0; filename mapping is in `assets/audio/README.md`.
- The established startup/Home Clear jingle, victory Clear jingle, failure jingle, and gameplay context loops are retained.
- Hard games, the final Strikes attempt, and the last quarter of Time Attack use the Failure loop; losses use Failure Jingle → Failure Loop.
- Entering Home through Menu requests the same Home/Clear cue used at startup, then continues the normal Home loop. Existing result transitions remain distinct and are not silently replaced.
- Help/About/Audio opened from gameplay preserve the gameplay music context; the same screens opened from Home keep the Home context.
- `V` remains a global mute/unmute shortcut and preserves the configured Music and FX levels.
- Music and FX have independent persisted 0–100% master levels. The defaults are Music 20% and FX 65%; result jingles use the FX master while background loops use the Music master.
- Input cues remain neutral in Classic/Daily and correctness-aware only where the game mode permits it.

## Responsive interface

- Home exposes mode and difficulty selectors plus New Game, Continue, and Daily Puzzle.
- Language selection uses bundled USA, Argentina, and Senyera assets without SDL_image.
- The desktop/XL sidebar uses a hierarchical control layout: full-width Menu, Pause/Restart, Hint/Notes/Verify, Sound/Help, numeric palette/progress, and a full-width About footer.
- Classic/Daily replace the non-informative Errors chip with a Hints count; Strikes/Time Attack retain Errors.
- Sound opens a dedicated Audio screen instead of consuming permanent sidebar space for volume controls.
- Portrait gameplay remains separately tuned, including its horizontal number palette.
- Regular desktop behavior is retained through 1366×768. At 1600×900 and larger, the XL tier grows the composition; 1920×1080 uses a 900-pixel board and 2560×1440/3440×1440 can use a 1080-pixel board.
- Help, About, and Audio keep bounded centered reading widths on large/ultrawide displays.
- About uses an explicit stack: full head, version/intro, a colored plain-language Sudoku-scale fact card with an SDL-drawn smiley, a separate cognition/study card, compact project/music credits, and four footer links.
- About never intentionally crops its fact/study copy; text-fit tests verify the complete translated copy at every supported diagnostic viewport.
- The study link points to Brooker et al. (2019), DOI `10.1002/gps.5085`, and the wording states association rather than causation.
- The fourth footer link is localized both in label and destination: `/donate/` (English), `/donaciones/` (Español), `/donacions/` (Català).

## Localization and branding

- User-visible interface text is routed through translation tables for English, Español, and Català.
- Exactly two v1.2 source branding masters remain under `assets/branding/source/`:
  - `sudokura-head.png` — Home, About, Pause, results, README/public identity.
  - `sudokura-512.png` — gameplay compact icon and all generated application/platform icons.
- Obsolete alternate, packed, and historical logo masters are removed from the active repository tree to prevent ambiguous asset authority.
- Derived PNG, ICO, ICNS, SDL window-icon, embedded head, and embedded flag resources are reproducible and require no SDL_image dependency.
- Language flags and their upstream MIT provenance remain vendored under `assets/flags/`.
- The approved canonical v1.2.0 screenshot lives at `docs/images/sudokura-v1.2.0.png`; README displays that single source as a scaled preview linked to the full PNG.

## Version and desktop packages

- `version.h` numeric major/minor/patch macros are the repository source of truth for v1.2.0.
- Package scripts reject externally supplied versions that disagree with source.
- Linux builds an x86_64 AppImage with fallback font, SDL2_mixer dependency closure, four OGG resources, and the generated application icon.
- Windows builds a portable x86_64 ZIP with GUI executable, embedded icon/version resources, fallback font, required non-system DLLs, and audio resources.
- macOS builds separate unsigned x86_64 and arm64 `.app` ZIPs with bundle-relative SDL2/SDL2_ttf/SDL2_mixer dependency closure, icon, font, and audio resources.
- No signing/notarization or manual platform launch is claimed unless performed separately.

## Automated validation

- Core tests cover deterministic generator revision 2 behavior, 1,200-seed stress coverage, uniqueness, difficulties, Daily identity, Restart, progress, hints, input behavior, conflicts, game-mode endings, localization, and responsive geometry.
- Persistence tests cover round trips, corruption, truncation, checksums, unsupported formats, incompatible generator revisions, semantic validation, Daily metadata, result states, and preference compatibility.
- Dedicated meaningful-progress tests cover pristine/elapsed-only sessions, entered values, notes, hints, mistakes, and completed sessions.
- Dedicated UI geometry tests cover the hierarchical gameplay controls, footer About placement, four-link About layout, and desktop sidebar balance across all diagnostic viewports and game modes.
- Dedicated keypad tests cover top-row digits, `SDLK_KP_0..9`, and physical keypad scancode fallback with Num Lock-style navigation keycodes.
- SDL_ttf tests measure gameplay, Help, complete About cards/credits/links, Audio labels, and all supported translations across ten viewports.
- SDL2_mixer tests exercise normal/failure contexts, result jingles, Home-context recovery, independent volume masters, mute, pause/resume, and generated UI/input effects with the dummy audio driver.
- Linux CI additionally runs AddressSanitizer and UndefinedBehaviorSanitizer against core and persistence tests.
- Diagnostic UI review renders ten viewports × seven screens = **70 non-canonical BMP frames** and validates dimensions/non-blank output.
- Linux, Windows, Intel macOS, and Apple Silicon macOS package previews remain required before release publication.

## Release process

- Package previews are non-publishing and use the exact pull-request/requested ref.
- Release tags must match the source version.
- Release automation can create a draft release only after all package jobs succeed; publishing remains a separate explicit action.
- The final Linux release-candidate application build (`7f0c6ec3ff7ceafb2a9b2cf1d0e834b344ede215`) was manually tested and approved before Stage B documentation finalization.
- The canonical v1.2.0 screenshot was supplied after that manual test and is versioned at `docs/images/sudokura-v1.2.0.png`.
- Stage B changes are documentation/screenshot-only and do not modify the tested application binary.

## Out of scope for v1.2.0

- Browser/WebAssembly packaging.
- Framework or language migration.
- Online accounts or network-backed puzzle services.
- Signed or notarized macOS distribution unless explicitly added and actually performed.
